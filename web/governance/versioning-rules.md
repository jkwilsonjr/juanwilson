# Versioning Rules

This document outlines guidelines for versioning documentation and files in this repository.

## Semantic Versioning
- Use semantic versioning (MAJOR.MINOR.PATCH) when labeling releases or significant document versions.
- Increment the **MAJOR** version for significant changes that are incompatible with previous versions.
- Increment the **MINOR** version for backwards-compatible feature additions or improvements.
- Increment the **PATCH** version for bug fixes or minor changes that do not affect the public API.

## Commit Messages
- Write clear and concise commit messages summarizing the changes.
- Use the imperative mood (e.g., "Update versioning guidelines").

## Tagging Releases
- Create tags on the main branch to mark official release points using the semantic versioning format.
- Include a short description of the changes associated with each tag.

## Document Updates
- When updating documentation, include a version history section at the end of the document to track changes over time.
